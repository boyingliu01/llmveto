# v2b-C 能力边界：provider 指纹巡检

> 本文是 v2b-C 的**能力声明**，与 `docs/protocol-capability-matrix.md` 同性质：
> 说明这个功能能做什么、**不能**做什么，以及为什么。目的是防止"装上了就以为被保护"。

## 一句话

网关会**周期性向受管 provider 发一个不含任何用户数据的探针**，从响应特征判断
该 provider 是否偏离其标称模型，并把结论记入 evidence。**它只告警，不阻断。**

## 它能做什么

| 能力 | 判据 | 检测周期 |
|---|---|---|
| 发现 tokenizer 变化 | 固定输入的 `usage.prompt_tokens` 偏离基线 >15% | 24h |
| 发现格式遵循退化 | 严格 JSON 输出失败（剥掉 markdown 围栏后） | 24h |
| 发现知识边界退化 | 极冷门事实答错（如"冰岛首都"） | 24h |
| 发现拒绝措辞变化 | 与基线文本的 Jaccard 相似度 <0.5 | 24h |
| 识别时间分片对抗 | 单维退化 + 补齐两维正常 → `inconsistent_degradation` | 按需 |

## 它**不能**做什么（重要）

### 1. 不阻断，不自动禁用；但会让 doctor 报 FAIL

即使确认某 provider 在被偷换，网关**也不会**：
- 阻断它的请求
- 自动切换到别的 provider

**但会让 `doctor` 报 FAIL**（2026-11-26 用户决策调整）。

理由：`doctor` 由用户显式运行，报 FAIL 不打断任何流量——它给出"这个 provider
有问题"的明确信号，又不承担误判的可用性代价。等积累足够数据证明 FP=0 后再谈阻断。

判据刻意保守：
- 无数据 → PASS（"还没测"不等于"测出问题"）
- 样本不足 K 窗口 → PASS + 标 `provisional`
- 样本足够且信任分 < 60 → **FAIL**

**信任分不流入 `verdict → action` 映射**——这条有断言把守（AC-10b）。

### 2. 探针本身可被上游识别，且可能被选择性放行

这是本功能最需要说清的一点。探针虽然：
- 不含任何会话内容（AC-01a 机械断言）
- 不含 hostname/路径/UUID/时间戳（AC-01b）
- 路径与主流量同形（AC-12b）
- UA 取自主流 SDK 列表（AC-12a）

但**它仍然可被识别**：
- **时序**：每 6h 一次，抖动只让规律变成"近似规律"
- **载荷结构**：四段固定文本，与真实对话形态不同
- **来源**：同一个出口 IP 的规律性探测

上游只要想看，就能看出"这台机器装了某个网关"。**这是用户接受的代价**（DR-002/DR-003）。

**最可能的对抗形态**：中转站识别出探针后，对探针返回**正常模型**、对真实流量返回
**偷换模型**。这是最省力也最有效的对抗，而且**无法防御**——它的判据就是"这次请求
像不像探针"。

**结论**：本功能**能发现"懒得针对你"的中转站，发现不了"专门针对网关用户"的中转站。**

**缓解：载荷换代**。`PAYLOAD_GENERATION` 让四段探针文本可以整组替换，使"识别探针"
变成军备竞赛而非一次性破解。换代时基线按代隔离（`baselineKey`），旧基线不与新观测
混算——换代即重建，重建完成前是 `baseline_pending`。

**换代的时机是"怀疑已被识别"，不是定期轮换**：每次换代都会让系统在重建窗口内失明，
而那个窗口恰好是攻击者的机会。

### 3. 完美时间分片对抗无法识别

轮转机制（`seq % 4`）让四次采样发生在不同时刻，系统**无法证明**四维退化来自
同一底层模型。对手若能在被观测的那一维始终给出对应质量，本功能看不出。

**具体怎么打**：中转站知道轮转规律后——

| 探针次序 | 测哪一维 | 返回 |
|---|---|---|
| 第 1 次 | D0 tokenizer | 真模型 |
| 第 2 次 | D1 格式遵循 | 假模型 |
| 第 3 次 | D2 知识边界 | 真模型 |
| 第 4 次 | D3 拒绝措辞 | 假模型 |

而**真实用户流量始终给假模型**。网关每次测到的都是真模型，四维全 clean、信任分
100——但用户一直在用假模型。

缓解手段（单维即 finding + 补齐探针）能抓住"不完美"的分片，但**抓不住完美的**：
补齐是"确认"手段，**发现不了从来没有任何一维退化的情形**。

### 4. 首次部署无判定

基线需要至少一次采样建立。在此之前状态是 `baseline_pending`，不产出 finding。
这既是宽限期也是盲区——刚装上网关的那 24 小时里，指纹维度没有防护。

### 5. 只在受管枚举内工作

判定域 = `MANAGED_CONFIG_IDS`。用户绕过网关直连的流量，指纹巡检看不到，
这与 v1/v2a/v2b-A 的边界一致。

## 频率与配额

| 约束 | 值 | 理由 |
|---|---|---|
| 基准周期 | 每 provider 每 6h ≤1 次 | 降低暴露 |
| 抖动 | ±20% | 破坏固定节律 |
| 手动与周期 | **共享配额** | 否则 CLI 是绕过最小暴露的侧信道 |
| 补齐 | 每 24h ≤1 次，最多补 2 维 | 判断分片不需要全集 |
| 熔断 | 连续 3 次失败 → 6h→12h→24h | 避免拖累主流量 |
| 超时 | 5s | 探针不能拖住任何东西 |

**熔断状态跨重启保留**（AC-09c/AC-20）——否则"重启即绕过退避"。

## 与相邻能力的关系

| 能力 | 关系 |
|---|---|
| `model-label-consistency` | **互补**：它查同一响应内 `model` 字段与请求是否自洽；指纹查跨请求的行为偏离 |
| `usage-reconcile` | 独立：它对账 token 计数，不做模型判定 |
| `doctor` | 互不影响：指纹**不驱动** doctor 的 PASS/FAIL |

## 用法

### 开关（默认关闭）

```bash
# 启用周期探针（默认不启用）
export LLMVETO_FINGERPRINT_PATROL=1
llmveto start
```

**默认关闭是刻意的**：一个已经在用的网关，不该因为升级就开始向中转站发请求。
那不是功能上线，是**机器的网络足迹静默改变**。只有显式设为 `1` 或 `true`
才启用；拼错（`yes`/`on`/`0`）一律不启用。

### 查询

```bash
# 查看各 provider 信任分（只读，不触发探针）
llmveto fingerprint

# 手动请求一次探针（仍受配额与退避约束）
llmveto fingerprint --probe opencode/whalecloud

# 看指纹结论是否让 doctor 报 FAIL
llmveto doctor
```

输出示例：

```
opencode/whalecloud: trust=100 (provisional) samples=3 findings=0 failures=0
```

`samples < 10` 时标 `provisional`：样本不足 K 窗口，分数仅供参考。

## 失败模式

| 现象 | 含义 | 处置 |
|---|---|---|
| `trust=100 provisional` | 还没测够 | 等待，或手动探针 |
| `findings > 0` | 检出偏离 | 看 evidence 里的 `dimension` 与 `deviation` |
| `failures > 0` | 探针发不出去 | 检查网络；连续 3 次会进退避 |
| `inconsistent_degradation` | 疑似分片对抗 | 最严重的信号 |

## 已知限制

**探针请求里的模型名来自 provider id 尾段**（`opencode/whalecloud` → `whalecloud`），
因为受管枚举里没有"该 provider 服务哪个模型"这一信息。真实支持需要用户配置，
不在 v2b-C 范围内。这意味着探针探测的模型可能与用户实际调用的模型不同。
