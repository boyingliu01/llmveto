## 2. P0 — 阻断性 / 安全相关

### P0-1 两个本地提交的归属处理（**最先做，其它都基于此**）
- **问题**：`main` 上有 2 个本机环境补丁提交（`b4cd220` archlint musl 补丁、`bb963c1` biome 修正），未推送。
- **为什么先做**：后续所有任务都从 `main` 开分支；这两个提交若留在 main 上，任何 PR 都会夹带无关改动。
- **可选方案**（需你拍板）：
  - (a) 长期保留 → 仍建议移到分支 `chore/dev-env-archlint-patch` 走 PR；
  - (b) 不作为仓库内容 → `git reset --soft origin/main` 撤回，补丁只留在本机（`postinstall` 会随撤回一起消失，需另记迁移说明）。
- **验收**：`git log origin/main..main` 为空或只剩本 PR 分支；`bun install` 后 archlint 仍可运行。

### P0-2 网关迁入 WSL systemd（TODO §3，**0/10 已完成**）
- **实测缺口**：`systemctl --user` 可用（systemd=true）、**无 llmveto unit**、8787/8790 端口空闲、dsh web 已在 3080 运行。
- **子项**：

### P0-3 ACP 客户端绕过网关的拍板（TODO §6 第一条）· **2026-11-23 复核后降级为「登记」**
- **机制**（已核实 `~/.dsh/profiles/web/cordis.patch.yml`）：网关靠改写客户端 `baseURL` 插在中间；普通 provider 有 `baseURL` 可改，而 trae/codebuddy 是 **ACP 子进程**，配置里只有 `command: /home/bull/.local/bin/traecli` + `args: [acp, serve]`，**没有 baseURL**。dsh 与它们用管道通信，流量根本不走 HTTP → 网关看不见。
- **影响**：canary / 命令扫描 / evidence 对这两个 provider 全覆盖不到。README 原文已声明此边界（"Installing the gateway ≠ being protected"）。
- **定位**：**架构边界，不是代码缺陷**。要覆盖需 v3 的 TLS 拦截（HTTPS_PROXY + 自建 CA），工程量大、且与"不装 CA 也能用"的现有承诺冲突。
- **2026-11-23 决策建议**：**接受风险 + 登记到 `docs/KNOWN-ISSUES.md`**，不删 provider（删了损失可用性，风险并未因删除而降低——用户随时可另装一个 ACP 客户端）。
- **验收**：`docs/KNOWN-ISSUES.md` 有明确条目 + README 边界声明已有（无需改）。

### P0-4 `dangerous-command-scan` 集成测试补齐（TODO §6）· **2026-11-23 已完成**

  - 把映射从 `finding: "warn"` 改为 `"block"` → **5 个用例变红**。

### P0-5 Gate 8 detect-secrets 实际未生效（TODO §5）· **2026-11-23 已修复**
- **根因**（读 `~/.config/xp-gate/adapters/gate-8.sh:316` 确认）：detect-secrets 只在
  `command -v detect-secrets-hook && [ -f .secrets.baseline ]` **两个条件同时成立**时才跑。
  本机 `detect-secrets-hook` 在 PATH 中，缺的正是 `.secrets.baseline` → 次防线静默不执行。
- **修复**：`detect-secrets scan > .secrets.baseline` 入仓（18 条已登记发现，逐条核实为
  测试夹具 / AWS 官方示例串 / git SHA / 源码常量，**无真实密钥**）。
- **连带问题（重要）**：baseline 文件内含已登记秘密片段，gitleaks 的
  `generic-api-key` 规则会命中它自身（实测 16 处）→ 必须在 `.gitleaks.toml` 豁免该路径。
- ⚠️ **踩坑记录**：gitleaks 8.30.1 下**只要存在自定义配置文件就不再自动加载内置规则集**。
  仅写 `[allowlist]` 会让 Gate 8 变成**沉默的假绿灯**（实测：无配置报 18 处，加坏配置报 0 处，
  连 `ghp_` GitHub Token 与 `AKIA` AWS Key 都扫不出）。正确写法是
  `[extend]` 段下的 `useDefault = true`；顶层 `extends = "default"` 同样失效。
- **验证**：正常态 PASS；新建 `ghp_` 探针 → gitleaks BLOCK（rule=github-pat）+ detect-secrets
  独立报出 GitHub Token / Base64 高熵串；新建 `AKIA` 探针 → BLOCK（rule=aws-access-token）。

- **方案评估**：按 provider 拆路由（改 `LLMVETO_UPSTREAMS` + `MANUAL_CANARY_MANAGED_ROUTES`）。

### P1-3 canary 容量评估（TODO §6）

### P1-4 流式 warn 语义一致性（TODO §6）
- 流式路径 warn 只进 `findings`，`action_taken` 保持 `allowed`（`src/gateway/core.ts` D-11，已核实注释在 L710/717）。
- **这是已知语义差异，不是 bug**：要统一需单独评审并改 spec。建议先登记 KNOWN-ISSUES。

### ~~P1-5 模型自述不一致~~ → **降级为 P3 观察项（2026-11-23 实测证伪）**
- **原记录**：`gemini-flash-lite` 自称 "GPT-4o"、`modelscope GLM-5.2` 自称 "GLM-4-9B"。
- **2026-11-23 直连官方端点实测**（不经任何中转）：

  | 模型 | 端点 | 自称 |
  |---|---|---|
  | ModelScope `ZhipuAI/GLM-5.2` | 魔搭官方 API | **"GLM-4"** |
  | Google `gemini-3.1-flash-lite` | Google 官方 API | **"GPT-4o"** |
  | Google `gemini-3-flash-preview`（对照） | Google 官方 API | **"Gemini 1.5 Pro"** |

- **结论**：对照组证明同家族模型也自报错误名字 → 这是**大模型"幻觉自述"通病**，**不能作为"被替换"的证据**。原 TODO 的判断（"自述不能作证据"）是对的，本次给出了实测支撑。
- **残留价值**：`GLM-5.2` 自称 "GLM-4" 仍值得用 **tokenizer 指纹**（同 prompt 的 `prompt_tokens` 是否与 GLM-5 家族一致）复核，因为魔搭是免费平台、存在挂小模型的动机。其余不必追。
- **附带发现（使用注意，非安全）**：GLM-5.2 推理 token 极重，`max_tokens=300` 时 298 个全是 reasoning、正文为空；需 `max_tokens ≥ 2000` 才能拿到正文。这是 `finish_reason=length` 的已知坑，探针脚本已支持 `--max-tokens` 放大重测。
- **建议**：P3 观察，不占 P1 名额。
